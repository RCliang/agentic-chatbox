Part 01

架构模式
Architecture Patterns

🏗️ Supervisor 模式 最常用

核心思路

一个 Supervisor Agent 作为调度中心，负责任务分发、结果汇总、异常处理。子 Agent 专注于单一领域。

Supervisor
调度 & 决策
→
研究员
代码生成
审查

适用场景

  • 任务有明确可分解的步骤
  • 需要不同专业能力的 Agent
  • 需要统一的质量控制
✓ 适合复杂工作流 ⚠ 单点瓶颈
def supervisor_node(state): # 决定下一步哪个 agent 工作 next_agent = router_llm.invoke(state) return {"next": next_agent}

🏛️ 层级式 vs 网络式编排

▶ 层级式 (Hierarchical)

多级 Supervisor 树形结构，高层 Agent 分解任务给中层，中层再委派给叶子 Agent。

# 层级：每个节点只关心下一级 class TopLevel(StateGraph): route_work → PM → Dev → QA
✓ 职责分明⚠ 延迟较高

◉ 网络式 (Networked)

Agent 之间直接通信，通过共享状态或消息队列协作。每个 Agent 可以主动向其他 Agent 发起请求。

# 网络：Agent 之间直接对话 AgentA.send(AgentB, query) AgentB.respond_with(result)
✓ 灵活⚠ 调试复杂

🧭 架构选择决策

  • 任务可线性分解？ → Supervisor 模式。一步接一步，Supervisor 统一调度。
  • 子任务依赖层级深？ → 层级式编排。多层分解，树形管理。
  • Agent 需要互相协商？ → 网络式协作。Agent 可互相调用，适用于辩论、协商场景。
  • 需要路由但避免单点？ → 动态 Router。用 LLM 判断路由，但加 fallback 防止卡死。
Part 02

状态管理
State Management

📦 State 设计原则

✅ 最佳实践

  • 用 TypedDict 定义强类型状态
  • 区分 共享状态 与 Agent 私有状态
  • 使用 add_messages reducer 累积消息
  • 状态尽量扁平化，避免深层嵌套
  • 用 Annotation 自定义缩减逻辑

❌ 常见陷阱

  • 所有 Agent 共享同一个巨大 State → 上下文污染
  • 频繁修改全局状态 → 竞态条件
  • 无限制的消息列表增长 → Token 爆炸
  • 状态中塞入 LLM 原始输出 → 不可预测的格式

📄 State 定义示例

from typing import Annotated, TypedDict, List from langgraph.graph import add_messages from langgraph.managed import IsLastStep class AgentState(TypedDict): # 消息历史 —— LangGraph 内置 reducer 自动追加 messages: Annotated[List, add_messages] # 当前任务描述（只读，不累积） task: str # 各 agent 的中间产出 —— 自定义 reducer agent_outputs: Annotated[dict, merge_dicts] # 当前由谁处理 current_agent: str # 最终结果 final_result: str | None def merge_dicts(a: dict, b: dict) -> dict: # 自定义 reducer：后写覆盖先写 return {**a, **b}
Part 03

Agent 通信 & 工具
Communication & Tools

💬 Agent 间通信模式

🔹 通过 State 通信（推荐）

  • Agent A 写结果到 state["agent_outputs"][A]
  • Agent B 从 state 中读取
  • 天然支持异步和重放
  • LangGraph 的 checkpoint 自动持久化
✓ 可追踪✓ 可调试

🔸 通过消息传递

  • Agent 之间直接发送 Command
  • 适用于需要实时协商的场景
  • 需配合 interrupt 实现等待
  • 注意循环引用检测
⚠ 复杂度高

🔧 工具注册与权限控制

工具设计原则

  • 每个工具职责单一
  • 输入输出类型明确
  • 提供清晰的文档字符串
  • 绑定 权限标签，限制敏感操作
@tool(name_style="lower_underscore") def search_knowledge_base(query: str) -> str: """搜索知识库。只读操作，所有 agent 可用。""" ...

Agent-工具绑定

  • 每个 Agent 只暴露必要的工具
  • 敏感工具（写数据库、发邮件）配审批节点
  • 用 bind_tools 按角色注入
# 研究员只有读权限 researcher = llm.bind_tools([search, read]) # 执行者有写权限 executor = llm.bind_tools([write_db, ...])
Part 04

可靠性工程
Reliability Engineering

🛡️ 错误恢复与兜底策略

重试策略

  • 指数退避重试 LLM 调用 + 工具调用各配 max_retries=3
  • 有条件重试 只在rate_limit / timeout 时重试，不可恢复错误直接上报

    • 兜底策略 (Fallback)

    • 降级 Agent：主 Agent 失败 → 简单规则 Agent
    • 超时中止：单 Agent 超时 → Supervisor 接管
    • 人工介入：关键节点用 interrupt 暂停，等待人工确认

    ⚙️ LangGraph 可靠性机制

    机制说明适用场景
    🔄 Checkpoint 自动保存每个节点的执行状态 崩溃恢复、调试重放
    ⏸️ Interrupt 在任意节点暂停执行，等待外部输入 人工审批、动态数据注入
    🔁 Node Retry 节点级别配置重试策略 LLM 调用失败、API 超时
    📌 Command 跨节点指令传递，支持 goto/resume 动态路由、错误恢复后跳转
    📝 State Validation 每个节点执行后校验状态模式 防止 State 结构污染
    Part 05

    测试 & 评估
    Testing & Evaluation

    🧪 多Agent 测试金字塔

    单元测试

    • Mock LLM 响应，测试 Node 逻辑
    • 测试 State 转换是否正确
    • 测试工具调用的入参/出参

    集成测试

    • 测试 2-3 个 Agent 的协作流程
    • 验证 Agent 间的消息传递
    • 测试错误恢复路径

    端到端测试

    • 真实 LLM，固定 seed
    • 验证最终输出质量
    • 测试超时、重试、降级

    评估 (Eval)

    • 定义质量指标：准确率、覆盖率
    • 使用 LangSmith trace 分析
    • 回归测试对比基线

    📊 评估示例

    Part 06

    生产部署
    Production Deployment

    🔭 可观测性三支柱

    📈 指标 (Metrics)

    • 每个 Agent 的调用耗时
    • 工具调用成功率
    • 总 Token 消耗
    • 工作流完成率
    Prometheus + Grafana

    🔍 链路追踪 (Tracing)

    • LangSmith / LangFuse
    • 追踪 Agent → Tool → LLM 调用链
    • 记录每次 State 变更
    ✓ LangSmith

    📋 日志 (Logging)

    • 结构化 JSON 日志
    • 每个 Node 的入/出参
    • 异常堆栈 + 上下文快照
    ELK / Loki

    ⚡ 性能与可扩展性

    水平扩展

    • 无状态 Node 支持并行执行
    • 使用 fan-out 并行分发子任务
    • Checkpoint 存储用 Postgres/Redis（非内存）
    • Graph 编译后缓存计算图

    Token 优化

    • 限制消息历史长度：只保留最近 N 轮
    • Agent 完成后清除其私有上下文
    • 使用 summarization node 定期摘要
    • 工具描述精简，只传必需的 schema

    🔒 安全边界设计

    Agent 权限隔离

    • 每个 Agent 有独立的 工具白名单
    • 敏感操作使用 interrupt 人工审批
    • LLM 输出校验（JSON Schema、正则）
    • 限制 Agent 可访问的 State 字段

    数据安全

    • State 中不存储明文密码/Token
    • 工具调用参数做 SQL 注入防护
    • 外部 API 调用限速（Rate Limiting）
    • 敏感数据脱敏后在传给子 Agent

    🎯 核心要点回顾

    🏗️ 架构

    根据任务复杂度选择 Supervisor、层级或网络模式。优先用 Supervisor，它最可控。

    📦 状态

    State 扁平化、强类型、职责分离。用 add_messages 管理消息，自定义 reducer 处理中间产出。

    🔧 工具

    每个 Agent 绑定最小工具集。敏感操作加审批。工具文档清晰、类型完整。

    🛡️ 可靠

    重试 + 降级 + 中断三位一体。Checkpoint 自动保存。人工兜底是最后防线。

    🧪 测试

    从单元到 E2E 逐层覆盖。用 LangSmith 做回归评估。Mock LLM 提高测试速度。

    🚀 生产

    指标 + 追踪 + 日志全覆盖。Token 预算管理。权限最小化原则。
